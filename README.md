# ProjectHealth AI v0.5 — OAuth integration

## Start on Mac (Docker Desktop + VS Code)

1. Extract this ZIP and open `projecthealth-ai-v05` in VS Code.
2. In the project root, run `cp .env.example .env`.
3. Edit `.env`: paste your **Asana Client ID** and **Client Secret** from Asana Developer Console. Do not share this file. Generate two independent random keys by running `openssl rand -hex 32` twice; paste the first as `TOKEN_ENCRYPTION_KEY` and the second as `JWT_SECRET`.
4. Ensure your Asana app's redirect URI is exactly `http://localhost:3001/api/asana/callback` and the scopes `projects:read tasks:read stories:read users:read workspaces:read` are selected. Keep distribution restricted to your workspace.
5. Stop the old Docker stack (from its original folder run `docker compose down` WITHOUT `-v`); then in this folder run `docker compose up --build`.
6. Visit http://localhost:5173, register/sign in, click **Connect to Asana**, authorise, choose a project, then click **Import & analyse**.
7. Click **Sync imported projects now** to refresh immediately. Background import refreshes approximately every 15 minutes while the backend runs; scores are generated by the existing task assessment scheduler. Refresh the dashboard to see new results.

## What is implemented

- Asana OAuth 2.0 authorization-code flow, one-time expiring state, server-side code exchange and token refresh.
- Encrypted Asana access/refresh tokens stored in PostgreSQL (AES-256-GCM).
- Workspace/project listing; task pagination; idempotent task upsert; read-only API scopes.
- Automatic task-based assessment, risk explanation, alerts, and periodic Asana task refresh.
- All existing v0.4 functionality remains.

## Important limitations

- This is a **local educational prototype**, not production-ready. No verified full end-to-end Docker test has been performed here.
- Scoring is heuristic, not a trained predictive model. Communication remains a neutral placeholder.
- Asana sync does not delete locally cached tasks removed in Asana. It supports up to 1000 tasks per project and reports an error if that limit is exceeded.
- OAuth project sync runs while the backend container is running. It is not a cloud hosted service.
- For a public deployment add HTTPS, hardened cookies/session management, key rotation, monitoring, rate limits, backup/recovery and comprehensive tests.
- If moving from v0.4, the new folder creates its own Docker volume. Do not use `docker compose down -v` on your previous folder; preserve the old data. To migrate existing records, use a proper database backup/restore process.

## Verification checklist

1. Register and sign in; confirm project list loads.
2. Connect to Asana; confirm Asana consent screen and return to localhost.
3. Import an Asana project containing a completed and an overdue task.
4. Confirm task names, assignees, due dates and calculated score appear.
5. Modify a task in Asana; click Sync and confirm the change.
6. Verify an at-risk project creates an alert; mark it read.
7. Export assessment CSV; inspect score history.
8. Restart Docker; verify login and Asana connection persist.

Never paste secrets in chat or screenshots. `.env` is ignored by git.

### Upgrade without losing data
If v0.5 was started from another folder, Docker Compose may create a **different named database volume**. To reuse the existing database, first run `docker compose ls` and `docker volume ls`, then either keep the same Compose project name with `docker compose -p <existing-project-name> up --build` or migrate the database using a verified backup/restore process. **Do not run `docker compose down -v`.** Back up data before any migration.

### Engine unit tests
`docker compose exec ai-engine python -m unittest -v test_engine`

The UI and tests must still be verified on the user's Mac. No live OAuth or full Docker integration test is claimed.
